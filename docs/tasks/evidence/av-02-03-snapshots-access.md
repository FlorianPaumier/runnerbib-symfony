# AV-02 / AV-03 — Immutable offers and authoritative shared-window access

Implemented locally on 2026-10-10; integration with SELL-03 is owned by the Identity/Selling specialist. No commit, external send or deployment.

`AvailabilityPublisher` is an inward-owned Application port implemented by `CaptureAvailability`; the database adapter and outbox writer share the seller transaction's Connection. Mutations require an owning transaction, take the race lock before the listing lock, snapshot the active membership rows and preserve original event identity, price, version, count and deadline. Same-version replay returns the existing offer without a new intent or changed recipients. Repricing creates a new event and invalidates old active versions. Withdrawal invalidates repeat-safely without replacing the original invalidation instant or immutable offer facts. An invalidated event cannot restart the same version. SELL-03 owns proof, seller-readiness, amount-bound and race-deadline validation before publication.

A newly captured event emits one typed `availability.batch_ready` intent; only event/listing/race IDs enter its payload. A failure in the owning transaction rolls back both snapshot and outbox. The consumer/batching work is NOTE-02, separate from these access facts.

`FindOfferAccess` queries by current listing or exact event and returns an Application `OfferAccessView`. A Domain policy derives priority/public/unavailable state from the persisted event instants and current authoritative facts. Nonempty snapshots restrict purchase initiation to original members until the exact deadline; empty snapshots are immediately public. Membership changes do not rewrite historical eligibility. At expiry, public access follows from time without a scheduled mutation. Late delivery never alters that instant. A current price/version, published race/listing, approved current proof and unchanged seller ownership are required. Suspended/unverified accounts, anonymous visitors and buyers who currently own a bib in the same race cannot initiate. Everyone can view the original priority deadline. Exact stale events, withdrawn/sold listings, races awaiting publication/archived and proofs awaiting revalidation are unavailable.

The accepted fail-closed DEC-01 rule is also enforced on reads: a missing or elapsed `race.resale_deadline` makes even an existing event unavailable. Synthetic fixtures explicitly set a future cutoff; no implicit production deadline was invented. The view includes the persisted nullable resale deadline. Cart/Checkout must use `canInitiatePurchase`, then repeat the authoritative query within their own locks before allocation. This read query allocates no reservation or checkout protection.
